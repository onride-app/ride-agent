# Local account admission after a Core grant

Prepared portfolio windows first inspect local scheduling without claiming a
ticket, registering a FIFO interest, sending a Core begin/poll, or touching
financial evidence. Busy, FIFO and pacing delays return private branded local
pending metadata. The bridge preserves the same portfolio entry and any real
Core pending pin, UUID, conservative booking and original 100-second FIRST
deadline. A local result is never a synthetic Core pending receipt. A busy
active account is checked before reading or replacing its operational-plan
attempt; fresh PG and exact pool/identity compatibility remain mandatory before
any later Core poll. Ordinary account/recovery paths retain their prior routing.

The probe is only a scheduling hint. After a real grant, the original local
admission gates run again and reject any race that no longer fits. The original
20-second active Core lease starts only at that actual grant; local deferral
does not extend the FIRST deadline, caller lifetime, account scope or provider
timeout. Cancel, expiry, foreign metadata and drain cannot convert a local
pending result into ownership of another live frame.

Core admission and the Node ledger remain separate gates. A granted frame may
wait before its first provider request only for the typed local pacing delay,
and only when quota, FIFO, exclusivity and quarantine are otherwise ready.
Every retry re-enters the same local gate. Other denials release unused Core
credit immediately; a pacing wait never allocates another frame or increases
the local reservation.

The original account scope, its monotonic deadline and the granted Core expiry
continue to run during the wait. The wire timeout remains at most 12 seconds
and cannot exceed the remaining scope. Fresh Perps submission evidence also
consumes the original execution expiry and a server-owned 20-second HTTP caller
lifetime. Disconnect, expiry and shutdown cancel waiting reads. A fresh
submission checks that caller lifetime again before its first outbox INSERT.
Already frozen or accepted actions retain their original outbox and recovery
path; a read cancellation does not cancel or replay an action.

An 80-weight audit followed immediately by a fresh preflight can therefore wait
the existing six-second pacing interval and then read again within the original
deadlines. Completed account data is not reused. History completeness, source
and account freshness, financial checks, quotas and sent-unknown accounting are
unchanged. These scheduling tests are local fixtures, not real-trade acceptance.

## Fresh submission scheduling purpose

Only the existing fresh Perps submit branch, after its original outbox SELECT,
may issue a private single-observation pacing purpose. The original execution
must still be queued, taskless, unretired, unexpired and match the unique frozen
record in that portfolio. An absent outbox is routing metadata, not exchange
absence, trading authority or permission to replay an unknown action. Existing
outboxes, recovery, unknown executions, Prediction and prepared children keep
their existing paths.

The runtime capability binds the configured bridge issuer, reader, budget,
original server HTTP caller and its original wall/monotonic cutoff, compact
portfolio control facts and original execution fingerprint. It cannot be made
from JSON, a boolean, a copied caller or an existing ALS/prepared scope. After
Core verifies the current account identity, it binds that exact cost owner,
scope and live FIFO interest and is consumed by one local reservation.

This purpose skips only the soft `nextObservationAt` predicate. Busy work and
the true FIFO head wait before PG-plan attempts and Core polls within the same
original lifetime. Core admission, local hard quota, fees, unknown debt,
exclusivity, quarantine and provider cooldown remain authoritative. Completion
still records the entire real cost and advances ordinary pacing; the old
schedule is never reset or refunded. FIRST100, Core20, caller20, provider12,
source/position5, account30, risk and frozen financial/outbox checks are
unchanged. A preceding Fixed286 observation creates21.45s soft spacing, which
cannot fit a fresh caller20 by waiting alone; this narrowly scoped scheduling
