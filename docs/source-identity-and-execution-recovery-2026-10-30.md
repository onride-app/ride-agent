# 持续源身份与原执行接受证明

2026-10-30。两个原组合各有一条来源停止更新，生产只读证据确认：
它们仍在推荐表和原前 100 名内，同一盐能唯一复原身份，但日评分超过
24 小时。Core perps_pool 的 fresh_only 过滤删除了来源身份，
Node 只能在这个临时名单解析旧 ID，于是持久组合得到 NOT_FOUND。

## 身份、评分和观察范围

既有组合的源读取、源成交历史和执行前复证改用独立身份目录及追加的
ride_agent_perps_source_identities。首次恢复旧 ID 时，只在私有 Core
有界分页返回的历史公开地址上验证原哈希；不外传盐，不替换交易员。
Core 仅返回身份和可空的最低观察范围，不返回新资格或财务状态。
已保存身份不依赖当前推荐服务，地址不可改变，RWA 范围只能升级。

未知范围不能默认为原生市场。旧 Candidate 的 RWA/外部 DEX 范围可要求
更严格观察；缓存或在途原生帧不能满足升级后的范围，旧 bridge 忽略新
提示也会被消费端拒绝。关闭 RWA 或缺少必要完整范围时明确失败。
所有实时帧仍保留实际取证时间及原 5 秒门槛。

新推荐仍要求原有效评分。每日复核只有确切 SCORE_UNAVAILABLE 可以
延期 60 秒并提示 review；不修改旧评分或成功复核时间，继续独立源读取
及全部原风控。其它身份、网络或证据错误仍按原规则阻止规划。
源消费诊断只记录原始时间、年龄、序号和随机 tick 引用；历史
last_source_at 推进不能单独证明执行或消费时新鲜。

## 未知提交不重放

无 task、已有原 outbox 但没有响应的 Perps 执行，改为仅查询原冻结字段的
接受证明，不再通过 perps_submit 恢复。已接受的原 task 继续原 ID 对账；
不完整、冲突、旧 Core、超时和无证明都保留 unknown。

not_accepted_expired 仅是未被接受的失败证据，不是成交或结算。
Core 必须在与提交一致的 admission 锁下检查过期、原记录缺席、完整证据
图和受保护的数据库关系。负证明还要求服务端配置的协议起点；起点不得
追溯到未经验证的旧写入服务。起点未配置时，原 task 仍可查询，但缺席
不会成为负证明。

两条 10 月 27 日的旧 unknown 缺少当时写入源码与完整交易所覆盖证据；
本补修不会把它们猜成 failed 或 completed，不会清理原 outbox 或换 ID。

## 发布和验收

先发布并核验私有 Core gRPC，再发布对应 API，最后发布 Node bridge、
backend 和 gateway。所有接口和表为追加，App 和 npm 不需要发布。
协议起点只能在新 Core 链路和旧实例退出已核验后设置当前时间。

本地测试、Git、云部署、自然来源恢复和真实跟单成交分别验收。
原账户自然验收须保留原模式、完整来源/账户范围、所有失败及冷启动；
只有原执行到 Core task、交易所成交和 owned receipt 的独立证据链才能
称为真实跟单恢复。合法风控拒绝、无自然事件、HTTP 成功或内部抵消均不
代替真实成交；不得为通过验收放宽限制或人工下单。
