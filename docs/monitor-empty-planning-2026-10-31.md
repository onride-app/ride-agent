# 零成功审计时跳过空规划事务

2026-10-31，本地性能补修候选。此变更去掉源码可以证明没有业务写入的事务；它尚未推送或部署，不能作为严格快照新鲜度已经修复的结论。补入 backend 发布与失败收尾延迟的负载模型仍然 **RED**。真实原账户自然验收、部署状态和实际跟单执行分别验证，App 不发新版。

## 行为与状态边界

`audit_control` 只为成功完成账户审计的组合登记审计 token。原 `observe_plan` 对缺少 token 的每个组合立即跳过；当 `audited.size === 0` 时，该事务不改变业务状态，只读取账户重试最小值，却仍执行 PostgreSQL 用户行锁、完整 JSON 更新和提交。

候选仅在上述条件成立时跳过 `observe_plan`。重试最小值改在本来就必须执行的 `durable_notify` 事务内，从新取得行锁后的当前状态计算；只有该事务真实提交成功后才发布到调度器。它仍保留原错误时间加 `retry_after_ms` 的绝对期限，不在失败收尾后再额外等待一整段重试时间。

只要存在一个成功审计，原三事务顺序、规划 callback 和 retry 发布位置全部保留。源证据、Fixed 历史、风控、金额、费用、保证金和策略规则未迁移或放宽。零成功审计时，C 仍处理原 execution ID 的未知结果对账、已冻结 queued 任务的 revision/attention/过期检查、日报、通知 prepare/rollback/committed 和后续 ACK。新增并发配置没有审计 token，不会得到新规划；迟到的公共源 DTO 只更新有界内存采样缓存，不回写已提交目标或历史游标。

retry 的读取时间从 B 后移到 C，因此两者之间的外部用户写入可能改变最终 hint；候选明确采用 C 锁内的当前状态。这不意味着所有并发调度时刻与旧代码逐毫秒相同。C 提交失败时，不发布新 hint 或启动未提交的通知发送。

## 本地验证

同一份冻结源码在独立本地 PostgreSQL 上运行完整 `npm test`：**1144/1144 PASS，0 skip，0 fail**。不是将跳过数据库的结果与数据库分组相加。另一个隔离数据库运行 `npm run test:functional`：**53/53 PASS**，覆盖真实本地 MCP、backend、OAuth、CLI 和 PostgreSQL；身份与交易所读写响应仍是模拟，不能当作真实签名、成交或原账户验收。

同份源码的 `npm run check`、`npm run build`、`npm run verify:package` 和 `git diff --check` 均通过。package 检查只在本地打包与临时目录安装，未发布 npm 包或 App。

新增回归先在未修改的 `2b3a0fa` 上保留 RED，再在候选上通过，覆盖：

- 完整 state、审计错误/performance、事件、原 unknown ID 与冻结 payload、通知 claim/ACK 的等价性。
- 真实延迟事务完成后，216ms 与 5200ms 绝对重试期限的实际调度时刻；前者第二次账户调用由旧路径的 4500ms 提前到 3200ms。
- A 提交与 C 加锁间的外部配置新增和修改，不规划未审计组合。
- C 提交失败时的通知回滚和 hint 发布边界。
- 真实 PostgreSQL MVCC、用户行锁、并发外部写入，以及迟到源 DTO 不改持久历史。

原 Runner 负载测试不再用事务次数 `% 3` 猜测阶段；它按真实 tick 记录首事务延迟，并从已有 monitor trace 读取实际阶段。原严格源、费用、配额、Fixed 游标和账户断言保留。

## 仍失败的后台延迟模型

原 direct CoreBridge 两账户/六来源负载没有 backend 发布及失败收尾延迟，原九项测试仍通过，500ms venue /200ms metadata I/O 的严格场景最大龄为 28.610/29.881s。这不能替代 backend 的可见快照年龄。

独立实验增加每次 backend state read 529ms、规划阶段 1346ms、durable 阶段 1252ms，并分别使用 675ms 和更强的 2460ms 返回到发布延迟。成功发布与后续 B/C 完成分开；失败及持久 future hint 先完成必须的事务，再根据原绝对期限决定剩余等待和正常 durable 周期。

这些输入来自未归属原账户的全局慢日志记录。记录受日志阈值截断，不能解释为原 owner 的完整延迟分布，也没有证明它们导致原账户线上失败。2460ms 是明确的额外合成发布 envelope。该 wrapper 也不是完整真实 AgentRunner。

| 相同输入下的源码/阶段模型 | 675ms 发布：两账户最大龄 | 2460ms 发布：两账户最大龄 |
| --- | --- | --- |
| `0ec0619`，保留空 B | 29.784 / 30.636s | 31.901 / 32.952s |
| `2b3a0fa`，保留空 B | 32.521 / 31.706s | 32.137 / 32.818s |
| `2b3a0fa`，跳过空 B | 30.102 / 31.158s | 32.008 / 32.518s |

上述所有行仍未通过严格 `<30000ms` 断言。实验保留失败退出码和完整报告，没有移动 warmup、边界或删除失败点。六个来源继续推进、380 行 Fixed 历史仍计费 39、原十五秒 offered grid、1000/60s 硬上限、完整 scope/foreign DEX/native 读取和原二十秒账户期限全部保留。实验使用 `MCP_NOOP_PIPELINE_EXPERIMENT=1` 显式运行，与常规回归分别报告。

此补修证明的是零成功审计时可以少做一次无业务事务，以及相关状态/提交语义通过本地验证；它没有证明原账户的完整新鲜度 SLO 已恢复，更不证明真实跟单自然执行成功。
